# 텔레그램 알림 연결

목표가나 손절선에 닿았을 때 텔레그램으로 알림을 받는 기능이다. 이 문서는
두 부분이다. 앞쪽은 **쓰는 사람에게 그대로 보내도 되는 안내**이고, 뒤쪽은
**운영하는 사람이 알아야 할 것**이다.

---

## 1. 쓰는 분께 보내는 안내

> 텔레그램 알림은 이렇게 연결합니다.
>
> **1) 사이트에 로그인합니다.** 오른쪽 위 👤 버튼으로 구글 로그인하시면 됩니다.
> 로그인을 안 하면 연결 코드가 만들어지지 않습니다.
>
> **2) ⭐ 관심 탭으로 가서 `📱 알림` 버튼을 누릅니다.**
> 6자리 코드가 뜹니다. 확인을 누르면 코드가 복사되고 봇 대화창이 열립니다.
>
> **3) 봇 화면 아래 `시작` 버튼을 누릅니다.**
> 이 버튼을 안 누르면 봇이 메시지를 받지 못합니다. 여기서 막히는 분이 제일
> 많습니다.
>
> **4) 복사된 6자리 코드를 붙여넣어 보냅니다.**
> "✅ 연결 완료!"라고 답이 오면 끝입니다.
>
> **5) 알림을 받으려면 종목에 목표가를 걸어두셔야 합니다.**
> 관심 탭에서 종목을 담고 목표가를 넣으면 도달했을 때 알림이 갑니다.
> 손절선 알림은 **매입가를 넣은 종목에만** 갑니다. 매입가는 선택사항으로
> 표시돼 있어서 그냥 넘어가시는 분이 많은데, 안 넣으면 -7% 알림이 오지
> 않습니다.

### 잘 안 될 때

| 증상 | 원인 |
|---|---|
| 코드를 보냈는데 답이 없다 | 봇 대화창에서 `시작`을 안 눌렀을 가능성이 가장 큽니다 |
| "6자리 연결 코드를 보내주세요"만 온다 | 코드가 아닌 다른 말을 보냈거나, 코드에 공백·오타가 섞였습니다 |
| "✅ 연결 완료"가 떴는데 알림이 안 온다 | 목표가를 안 걸었거나(목표가 알림), 매입가를 안 넣었습니다(손절 알림) |
| 코드를 다시 보니 아까와 다르다 | 정상입니다. 한 번 쓴 코드는 바로 새 값으로 바뀝니다 |
| 연결했는데 조용하다 | 조건에 닿은 종목이 없으면 알림은 안 갑니다. 알림이 없는 게 정상인 날이 많습니다 |

연결 확인까지 **최대 5분** 걸립니다. 코드를 보내고 바로 안 된다고 다시
보내지 않으셔도 됩니다.

---

## 2. 운영하는 사람이 알아야 할 것

### 봇 아이디를 반드시 채워야 한다

`index.html`의 `TELEGRAM_BOT_USERNAME` 한 곳이다.

```js
const TELEGRAM_BOT_USERNAME = '@여기에_봇이름_입력';  // 예: @richman_alert_bot
```

**이 값이 비어 있으면 아무도 연결을 끝낼 수 없다.** 안내 문구에 봇 이름이
그대로 들어가기 때문에, 사용자에게 "@여기에_봇이름_입력을 검색하세요"가
나간다. 값을 안 채운 동안에는 연결 안내 대신 "아직 준비되지 않았습니다"가
나가도록 막아뒀다. 엉뚱한 지시를 내보내는 것보다 낫다.

봇 아이디는 텔레그램에서 `@BotFather`에게 `/mybots`를 보내면 확인할 수 있다.
값을 채우면 안내 문구와 `t.me` 주소가 같이 바뀐다.

### 왜 검색이 아니라 주소를 여는가

예전 안내는 "텔레그램에서 봇을 검색하세요"였다. 텔레그램 검색은 비슷한
이름의 다른 봇을 같이 보여주고, 알림 봇을 사칭하는 계정이 실제로 있다.
주소를 바로 열면 그 위험이 없고 단계도 하나 줄어든다.

### 연결이 처리되는 방식

```
사용자가 봇에게 6자리 코드 전송
        ↓  (5분마다 실행)
scripts/telegram_link.py — getUpdates로 새 메시지를 읽는다
        ↓
Supabase profiles에서 link_code가 일치하는 행을 찾아
telegram_chat_id를 저장하고, 동시에 link_code를 새 값으로 바꾼다
        ↓
"✅ 연결 완료!" 회신
```

코드를 저장과 동시에 갈아 끼우는 이유가 있다. 화면 캡처나 로그로 코드가 한
번 새어 나가면, 그 코드를 남이 봇에 보냈을 때 알림이 그 사람 대화방으로
넘어간다. 한 번 쓰면 죽는 코드여야 한다.

`data/telegram_offset.json`이 어디까지 읽었는지 기억한다. 이 파일을 지우면
예전 메시지를 다시 읽어 이미 연결된 사람에게 회신이 다시 갈 수 있다.

### 알림이 안 갈 때 어디를 보나

1. **연결 자체가 안 됐나** — Supabase `profiles`에서 그 사용자의
   `telegram_chat_id`가 채워졌는지 본다.
2. **조건이 안 닿았나** — `scripts/user_alerts.py`(목표가)와
   `scripts/user_exit_alerts.py`(손절·트레일링)가 각각 따로 돈다.
   손절 알림은 매입가가 있어야만 평가된다 (`scripts/exit_signals.py`).
3. **봇이 차단됐나** — 사용자가 봇을 차단하면 발송이 실패한다. 실행 로그에
   실패가 찍히는데, chat_id는 뒤 세 자리만 남는다.

### 로그에 무엇이 남는가

이 저장소는 공개다. 연결 코드와 chat_id는 `common.py`의 `mask()`를 거쳐
뒤 세 자리만 남긴다. `mask()`가 `telegram_link.py` · `user_alerts.py` ·
`user_exit_alerts.py` 세 곳에 각각 복사돼 있어서, 마스킹 규칙을 바꾸려면
세 곳을 다 고쳐야 한다.

### 필요한 환경변수

`TELEGRAM_BOT_TOKEN` · `SUPABASE_URL` · `SUPABASE_SERVICE_KEY`.
하나라도 없으면 `telegram_link.py`는 조용히 종료한다(exit 0). 실패로
잡히지 않으므로, 연결이 안 되는데 워크플로가 초록색이면 이쪽을 먼저 본다.
