두 가지를 다룹니다.

1. 하루에 몇 명이 들어왔고 **어디서 왔는지**를 매일 아침 텔레그램으로 받기
2. `clarm3126-prog.github.io/richman/` 대신 **stage2.kr**을 쓰기

코드는 이미 올라가 있습니다. 아래 설정만 해주시면 됩니다.

# 1부. 방문자 집계

## 어떻게 도나

```
사람이 사이트를 연다
  → index.html이 page_hits 테이블에 한 줄 넣는다 (하루 한 번, 브라우저당)
  → 매일 09:10 KST에 Actions가 그걸 세서 텔레그램으로 보낸다
```

새로 가입할 서비스가 없습니다. 이미 쓰는 Supabase와 텔레그램으로 끝납니다.

## 무엇을 저장하고 무엇을 저장하지 않나

| 저장한다 | 저장하지 않는다 |
|---|---|
| 날짜 | IP 주소 |
| 유입원 (`threads` / `youtube` …) | 브라우저·기기 정보 |
| 경로 (`/richman/`) | 누구인지 알 수 있는 값 |
| 브라우저가 만든 임의 번호 | 로그인 정보와의 연결 |

임의 번호는 **같은 사람을 두 번 세지 않으려고만** 씁니다. 그 번호로는
누구인지 알 수 없고, 방문자가 브라우저 기록을 지우면 새 번호가 됩니다.

저장소가 Public이라 텔레그램 메시지와 Actions 로그에도 **숫자만** 나갑니다.

## 설정 — Supabase에서 SQL 한 번 실행

Supabase 대시보드 → **SQL Editor** → 아래를 붙여넣고 Run.

```sql
-- 방문 기록. 개인 식별 정보는 넣지 않는다.
create table if not exists public.page_hits (
  id        bigserial primary key,
  seen_at   timestamptz not null default now(),
  day       date not null default (now() at time zone 'Asia/Seoul')::date,
  src       text,
  path      text,
  visitor   text
);

create index if not exists page_hits_day_idx on public.page_hits (day);

alter table public.page_hits enable row level security;

-- 넣기만 할 수 있다. 로그인한 사람과 안 한 사람 둘 다 해당된다.
-- 로그인하면 역할이 anon에서 authenticated로 바뀌기 때문에,
-- anon만 적어두면 로그인한 사람의 방문이 통째로 빠진다.
create policy "visitors can insert hits"
  on public.page_hits for insert to anon, authenticated with check (true);

-- 읽기 정책은 만들지 않는다.
-- 그래서 사이트에 박혀 있는 anon 키로는 남의 방문 기록을 읽을 수 없고,
-- 집계 스크립트만 service key로 읽는다.
```

### 오래된 기록 지우기 (선택)

그냥 두면 계속 쌓입니다. 90일이 지난 줄을 매일 지우려면:

```sql
create or replace function public.prune_page_hits()
returns void language sql security definer as $$
  delete from public.page_hits where day < current_date - 90;
$$;
```

Supabase의 **Database → Cron**(pg_cron)에서 하루 한 번 부르게 하거나,
가끔 SQL Editor에서 직접 실행하셔도 됩니다.

## 설정 — GitHub Secrets

이미 다 있습니다. `Visit Summary` 워크플로가 쓰는 것:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_KEY`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

없는 게 있으면 `user-alerts` 워크플로가 같은 걸 쓰니 거기서 확인하세요.

## 확인하는 법

1. 위 SQL을 실행합니다.
2. 사이트를 한 번 엽니다 (`?from=test`를 붙여서 열면 유입원도 같이 확인됩니다).
   ```
   https://clarm3126-prog.github.io/richman/?from=test
   ```
3. Supabase → **Table Editor → page_hits**에 한 줄이 생겼는지 봅니다.
4. Actions → **Visit Summary** → Run workflow → `dry_run` 체크 → 실행.
   로그에 집계가 찍히면 성공입니다.

첫날은 `dry_run`으로 돌려보고, 숫자가 맞으면 그냥 두면 매일 아침에 옵니다.

## 유입원 꼬리표

쓰레드·인스타는 **앱 안 브라우저로 열려서 referrer가 안 남습니다.** 그래서
링크 끝에 꼬리표를 붙여야 구분됩니다.

자동으로 붙는 것 (`content/social.yml`의 `link.source_param`):

| 어디서 | 링크 |
|---|---|
| 쓰레드 답글 | `...?from=threads` |
| 인스타 DM·답글 | `...?from=instagram` |

**손으로 넣어야 하는 것:**

| 어디에 | 링크 |
|---|---|
| 유튜브 설명란 | `...?from=youtube` |
| 유튜브 고정 댓글 | `...?from=youtube` |
| 블로그 | `...?from=blog` |
| 인스타 프로필 링크 | `...?from=bio` |

꼬리표는 주소창에서 자동으로 지워집니다. 방문자에게는 깨끗한 주소로 보이고,
같은 방문 안에서는 기억해두므로 페이지를 옮겨 다녀도 유입원이 유지됩니다.

## 방문자보다 중요한 숫자

요약 맨 아래에 **텔레그램 연결 수**가 같이 옵니다. 방문은 스쳐 지나가지만
연결은 남습니다. 유튜브가 효과가 있는지 볼 때 이 숫자가 먼저입니다.

# 2부. stage2.kr 연결하기

지금 주소는 `clarm3126-prog.github.io/richman/` 입니다. 길고, 소개 카드에는
이미 "stage2.kr"이라고 적어두셔서 서로 맞지 않습니다. 유튜브 설명란에
넣기에도 짧은 주소가 낫습니다 — 특히 시니어 시청자는 주소가 낯설면
누르지 않습니다.

## 0단계. 도메인이 있는지 확인

`stage2.kr`을 아직 안 사셨다면 먼저 사야 합니다. `.kr`은 국내 등록기관에서
삽니다 — 가비아, 후이즈, 카페24 등. 보통 연 1~2만원대입니다.

**이미 갖고 계시면 1단계로 갑니다.**

## 1단계. DNS에 레코드 넣기

도메인을 산 곳(가비아 등)의 **DNS 관리** 화면에서 넣습니다.

### 루트 도메인 (`stage2.kr`) — A 레코드 4개

| 타입 | 호스트 | 값 |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

네 개를 **전부** 넣어야 합니다. 하나만 넣으면 그 서버가 쉴 때 사이트가
안 열립니다.

### www도 쓰려면 — CNAME 하나

| 타입 | 호스트 | 값 |
|---|---|---|
| CNAME | `www` | `clarm3126-prog.github.io` |

끝에 점(`.`)을 요구하는 곳도 있습니다. 화면 안내를 따르세요.

## 2단계. GitHub에 알려주기

저장소 → **Settings → Pages → Custom domain** 에 `stage2.kr` 입력 → Save.

GitHub이 저장소에 `CNAME` 파일을 자동으로 만듭니다. **이 파일을 지우면
연결이 풀립니다.**

DNS가 퍼지는 데 보통 10분~한 시간, 길면 하루가 걸립니다. 그동안 GitHub
화면에 "DNS check in progress"가 떠 있는 건 정상입니다.

## 3단계. HTTPS 켜기

같은 화면에서 **Enforce HTTPS**에 체크합니다. DNS 확인이 끝나야 체크할 수
있으니, 회색이면 조금 기다렸다 다시 들어오세요.

인증서는 GitHub이 알아서 발급합니다. 따로 살 것 없습니다.

## 4단계. 주소를 바꿔야 하는 곳 (중요)

도메인만 연결하고 끝내면 안 됩니다. 코드 세 곳이 옛 주소를 갖고 있습니다.

| 파일 | 무엇 | 안 바꾸면 |
|---|---|---|
| `content/social.yml` → `link.url` | DM·답글로 보내는 링크 | 계속 긴 주소가 나감 |
| `scripts/social/config.py` → `PAGES_BASE` | **인스타 카드 이미지 주소** | 인스타 발행이 실패할 수 있음 |
| `docs/유튜브_대본.md` → 설명란 고정 문구 | 유튜브 설명란 | 영상에 옛 주소가 나감 |

`PAGES_BASE`가 특히 중요합니다. 인스타는 이미지를 **직접 내려받아야** 해서
접속 가능한 공개 주소가 필요합니다. 주소가 틀리면 카드가 안 올라갑니다.

바꾼 뒤에는 Actions에서 `Social Post`를 `dry_run`으로 한 번 돌려 카드
주소가 제대로 나오는지 확인하세요.

### 옛 주소는 계속 열립니다

`clarm3126-prog.github.io/richman/`로 들어와도 새 주소로 넘어갑니다.
그동안 DM으로 보낸 링크가 죽지 않으니 급하게 뭘 정리할 필요는 없습니다.

## 5단계 (선택). Cloudflare를 앞에 두기

도메인 네임서버를 Cloudflare로 옮기면 따라오는 것들이 있습니다.

- 접속이 조금 빨라집니다 (국내 캐시)
- **Cloudflare Web Analytics**를 공짜로 켤 수 있습니다 — 1부의 집계와
  별개로, 페이지별·국가별 통계를 덤으로 봅니다
- `www.stage2.kr` → `stage2.kr` 같은 정리가 쉬워집니다

다만 GitHub Pages 앞에 Cloudflare를 둘 때는 SSL 모드를 **Full**로 두셔야
합니다. Flexible로 두면 접속이 무한히 반복되는 문제가 생깁니다.

급하지 않습니다. 1~4단계만 해도 충분합니다.
