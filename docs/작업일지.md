# 작업일지

세션 셋이 같은 저장소를 만진다. 커밋 메시지는 **무엇을** 바꿨는지는 남기지만
**왜** 그랬는지, 그래서 **다른 세션이 뭘 알아야 하는지**는 못 남긴다. 그걸 여기 적는다.

```
쓰레드 브랜딩(12317)        쓰레드 글·대기열·발행 파이프라인·사이트 문구·블로그 원고
쓰레드, 블로그 자동화(12316)  댓글 자동화 (네이버 블로그 댓글 + 쓰레드 답글)
DM자동화(12318)            DM 자동화
```

## 적는 법

- **일이 끝날 때** 한 줄. 시작할 때 말고.
- 맨 위가 최신. 날짜 밑에 `- 세션이름 — 내용` 형식.
  ⛔ **`>>` 로 파일 끝에 붙이면 안 된다.** 맨 아래에는 `## 🔁 재부팅 뒤 이어받을 것`
  두 덩이가 있어서, 붙인 글이 **가장 오래된 날짜보다도 아래**로 내려가 안 보인다.
  (2026-09-29, 12318 의 아홉 덩이가 그렇게 묻혔다. 12316 이 찾아 옮겼다 `051a8087`)
  → 그날 제목을 앵커로 잡고 **그 뒤에 끼워 넣는다.** 앵커에 **`\r\n` 을 써야 한다** —
  이 파일은 CRLF 라 `## 2026-09-29\n` 으로 찾으면 **조용히 아무 일도 안 일어난다.**
- 남이 알아야 할 것만. 내 안에서 끝난 일은 안 적는다.
- 특히 이런 건 꼭 적는다.
  - 남이 쓰는 파일·스크립트의 **동작**을 바꿨을 때
  - **숫자나 문구의 기준**이 바뀌었을 때 (다른 세션이 옛 기준으로 글을 쓴다)
  - 워크플로·크론·발행 시각을 건드렸을 때
  - 손대는 중이라 **당분간 건드리면 안 되는 파일**이 있을 때

세션을 열면 지난 24시간 커밋이 자동으로 뜬다(`scripts/session_brief.py`).
여기는 그걸로는 안 보이는 것만 적으면 된다.

**이 파일은 셋이 같이 쓴다.** `git add docs/작업일지.md` 를 하면 그 순간
남이 쓰던 줄까지 같이 담긴다. `git add -A` 를 안 쓰는 것으로는 못 막는다 —
파일을 골라 담아도 같은 일이 난다(2026-09-20, `f870a912` 에 12318 항목이
딸려 들어갔다. 내용은 그대로라 손해는 없었다).

그래서 이렇게 한다.

- **적었으면 바로 커밋한다.** 오래 들고 있을수록 남의 커밋에 실린다.
- 남의 항목이 내 커밋에 실려도 **되돌리지 않는다.** 내용이 남아 있으면 된
  것이고, 되돌리려다 지우는 쪽이 더 나쁘다. 실렸다는 것만 서로 알리면 된다.
