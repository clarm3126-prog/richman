# 조용한 고장 — 값이 0이나 빈칸으로 왔는데 그게 답인 줄 안 것

세 세션(12316·12317·12318)이 **같은 고장을 각자 따로 겪었다.** 흩어 적으니
다음 사람이 또 처음부터 겪는다. **여기 한 군데에 쌓는다.**

## 규칙

> **0 이나 빈칸이 나오면 "정말 0인가, 못 센 건가"를 먼저 가른다.**

- 에러가 안 났다고 성공이 아니다. **실패가 값의 모양으로 온다.**
- 못 읽은 것을 기록에 남기지 않는다. 한 줄이라도 적으면 "처리함"이 되어 다시 안 본다.
- 판정에는 **근거를 같이 남긴다.** 나중에 틀렸다는 걸 알았을 때 되짚으려면 필요하다.
- 검사기가 조용하면 **잡을 힘이 있는지 따로 시험한다.** 일부러 깨뜨려 보고 잡는지 본다.
- **에러로 죽은 것과 결과가 0 인 것은 다르다.** 종료코드를 같이 찍는다.
  `2>/dev/null` 은 **죽음을 0으로 바꾼다.** 훑을 때는 붙이지 않는다.
- ⭐ **검사기가 무언가 찾았을 때가 제일 위험하다.** 찾았으니 맞다고 믿게 된다.
  걸린 줄은 **눈으로 보고**, 고치기 전에 **그게 지금 돌고 있는지**부터 확인한다.
  (2026-09-29, 두 세션이 각각 다른 방법으로 같은 멀쩡한 파일을 고장이라 읽었다.
   멈춘 건 한쪽이 '오늘 이걸로 카드 8장을 찍었다'는 실물을 갖고 있어서였다.)

## 어떻게 잡았나 — 공통점

**혼자서는 한 번도 못 잡았다.** 위 표에 있는 것 가운데 혼자 앉아서 찾아낸 건 하나도
없다. 다른 세션이 같은 값을 다른 방법으로 세다가 어긋나서 드러났다.
⚠️ 건수를 여기 적지 않는다. 줄이 늘면 그 숫자만 낡는다(실제로 아홉으로 적혀 있었다).

→ **값을 주고받을 때 값만 주지 않는다.** 어느 파일 어느 키인지, 모집단이 무엇인지,
그 파일이 얼마 만에 갱신되는지까지 같이 적는다.
